# exvia 需求说明书

## 项目背景

我们的部分服务器处于网络管控较严的环境中：出站方向只有少数端口可用，SSH（22 端口）等常用运维端口一律封禁，UDP 也不保证可用。在这种环境里，ssh、scp、rsync 等常规运维手段全部失效，机器出了问题只能人到现场，或者走流程申请开通临时端口，效率很低。

调研过的现有开源远程管理与隧道工具包括 frp、chisel、wstunnel、gost、Teleport、MeshCentral、Tailscale、RustDesk 等，都不能同时满足要求：

- 能在出站端口严格受限的网络里工作；
- 用 Rust 实现，代码完全自主可控；
- 内置交互终端、文件传输、端口转发能力；
- 把中继服务器当作不可信组件对待，中继读不到会话内容。

纯隧道类工具（frp、chisel、wstunnel）只有转发能力，没有终端和文件功能，而且隧道内容在中继上是明文；功能最全的 Teleport 体量太大，社区版是 AGPL 协议；MeshCentral 是 Node.js 实现，也不满足要求。因此自研，项目代号 exvia。

## 项目目标

用 Rust 实现一套轻量的、可自托管的远程运维工具，由三个组件组成：

中继（exvia-relay）部署在公网 VPS 上，以独立系统服务的方式运行，自带 TLS，独占一个可配置的监听端口，不依赖也不复用机器上已有的 HTTPS 服务。它只负责登记在线机器、撮合会话、搬运加密字节，不承载任何业务逻辑。设计上把它当作"随时可能被攻陷"的组件对待：会话内容从被控端到 CLI 全程端到端加密，中继被拿下也读不到任何会话明文。

被控端（exvia-agent）运行在被管机器上，只向中继发起出站连接，本机不监听任何端口。它接收操作指令，提供交互终端、文件传输和端口转发服务。

CLI（`exvia`）运行在操作者自己的电脑上，是日常使用这套系统的主要入口。

整体目标：在出站受限的网络里，操作者用 exvia 操作远端机器，感受接近使用 ssh。

## 安全与不可探测性

这里说明要达到什么，具体怎么保证见概要设计的"安全与不可探测性"一章。

安全性要求：

1. 中继不可读。会话内容在被控端与 CLI 之间端到端加密，中继上无论是抓网络包还是翻它的本地存储，都拿不到会话明文。中继只保存运行必需的元数据（哪些机器在线、什么时间谁开过会话、传输了多少字节）。
2. 身份可信。被控端凭一次性令牌注册，之后用私钥签名认证；CLI 与中继之间、会话两端之间都有指纹校验机制，中间人攻击会被发现。
3. 权限最小。被控端本机不监听任何端口；本地密钥文件权限 0600；令牌一次性、可撤销。

不可探测性指的是流量层面，能保证的是：通信全程 TLS 加密再套端到端加密，任何中间设备都读不到内容；协议外形就是标准的 WebSocket over TLS，没有自定义协议特征可供识别；中继独占自己的端口，不与现有 HTTPS 服务搅在一起；对中继端口的普通网页访问返回一个正常页面，端口扫描和偶然访问看不到异常。

能力上限：出口处仍然能观察到"有一条加密长连接指向中继的 IP 和端口"，连接的存在性、流量大小和时间规律无法隐藏。exvia 不是匿名工具，对抗不了对出口流量做主动关联分析的审查者。

明确不做的：主机层面的隐藏——进程隐藏、文件隐藏、对抗杀毒软件和 EDR——不在目标范围内，也不会实现任何相关功能。

## 名词解释

| 名词 | 含义 |
|---|---|
| 中继 | 部署在公网的中转服务，所有连接的汇聚点，只见密文 |
| 被控端 | 被管机器上常驻的 agent 程序 |
| CLI | 操作者本机上的命令行程序（`exvia`），日常入口，负责签发会话票据 |
| 会话 | 一次具体操作（开终端、传文件、转发端口）所占用的通道 |
| 会话票据 | CLI 用长期私钥对会话参数签名的凭证，被控端验签通过才建立会话，中继无权伪造 |
| 注册令牌 | 管理员签发的一次性入网凭证，被控端首次接入时使用，用后作废 |
| 机器标识 | 被控端身份公钥的指纹，注册后由中继分配，用于日常指代一台机器 |
| 指纹固定 | 把对方证书/公钥的哈希值记录下来，之后连接时不一致即拒绝并告警 |

## 使用场景

场景一：上线一台新机器。管理员在中继上生成一个一次性注册令牌，把被控端程序连同"中继地址（含端口）+ 令牌 + 中继证书指纹"带到目标网络内的机器上执行注册。注册成功后这台机器常驻在线，此后不再需要令牌。被管机全程不需要开放任何入站端口。

场景二：日常登录运维。操作者运行 `exvia ls` 看到所有在线机器，`exvia shell web-01` 直接进入交互终端，vim、htop、Tab 补全都正常，和 ssh 登录后的体验一致。

场景三：传文件。`exvia put`、`exvia get` 在本机与被管机之间传文件，自动做完整性校验，传输过程显示进度。

场景四：访问机器上已有的服务。`exvia forward` 把被管机的某个端口映射到本地，之后照常使用系统自带的 ssh、数据库客户端、浏览器访问——比如把被管机的 22 端口映射到本地 8222，然后 `ssh -p 8222` 登录，SFTP 也随之可用。

场景五：检查使用记录。管理员查看审计日志，知道谁在什么时间对哪台机器开过什么会话、持续了多久。

场景六：网络不稳的环境。被管机网络闪断、中继重启之后，被控端自动重连恢复在线，不需要人工到现场处理。

## 功能需求

端到端加密。被控端与 CLI 之间用 Noise 协议建立加密会话，中继只搬运密文和路由信息，会话内容对中继不可读。

指纹固定。注册时校验并记录中继证书指纹，首次会话时记录会话对端公钥指纹；之后任何一次连接指纹对不上，立即拒绝并明确告警。

反向注册与上线。被控端只向中继发起出站 WebSocket（WSS）连接。首次上线凭一次性注册令牌完成注册，注册成功后本地保存身份密钥（文件权限 0600）。之后每次连接不再需要令牌：由中继下发随机挑战数，被控端用私钥签名应答，中继验签通过才算上线。被控端全程不监听任何入站端口。

独立服务模式。中继以系统服务方式部署：自带 TLS（首次启动自动生成证书并输出指纹，供注册时校验固定），独占一个可配置的监听端口，与机器上已有的 HTTPS 服务互不干扰。被控端同样以系统服务方式常驻：安装即开机自启、进程崩溃自动拉起，不需要人守着前台进程。

在线状态。被控端每 30 秒发一次心跳，中继 90 秒收不到心跳即标记离线。`exvia ls` 列出所有机器的标识、主机名、系统与架构、被控端版本和最后活跃时间。

交互式终端。`exvia shell` 进入远端交互终端。要求分配真实 PTY：vim、htop 等全屏程序正常工作，本地终端窗口大小变化实时同步到远端，Ctrl-C 等控制字符原样透传，远端命令退出后本地能拿到退出码。

一次性命令执行。`exvia exec <机器> -- <命令>`，分别回传标准输出、标准错误和退出码，支持设置超时；`exec -t` 强制命令在远端 PTY 里运行（`ssh -t` 语义：TERM/CRLF/resize 与交互终端一致，单机，退出码与超时语义不变）。

文件传输。`exvia put` / `exvia get` 传输单个文件，按 60000 字节分块传送（一条 Noise 记录的上限），SHA-256 校验完整性；接收端先写临时文件、校验通过后再改名落盘，不会残留半截文件；传输过程显示进度。`get` 支持远端尾分量通配符（`get 机器 '远端/*.log' 本地目录/`，引号防 shell 展开：agent 在远端父目录内按尾分量匹配——不匹配隐藏文件、只支持尾分量——匹配结果按既有树下载路径落进本地目录，无匹配明确报错）。`put` 支持多机分发（`put m1,m2 <本地...> <远端>`：同一组源并发传到每台机器，输出带机器前缀、末尾逐机汇总，任一失败整体退出码非零）。

目录传输。`put -r` / `get -r` 递归传输整棵目录树：一次 Noise 会话传完，不逐文件握手；保留权限位与修改时间、还原空目录，符号链接不跟随、不传输；路径安全由接收端独立校验（拒绝 `..`、绝对路径与符号链接逃逸），即使 CLI 侧被攻破也写不到授权目录之外。

断点续传。单文件传输中断后可用 `--resume` 从断点继续（续传不恢复会话本身，而是重开一次传输、从已落盘分片补齐剩余字节）：分片留在目标同目录，续传握手先比对已收前缀的 SHA-256，对不上就回退一个分块、仍对不上则从头传，绝不把不一致的分片拼接进结果；收尾完整性校验与首传相同。

TCP 端口转发。`exvia forward -L 本地端口:目标地址:目标端口 <机器>`，支持多条并发连接；目标可以是被控端能访问的任意地址（包括它自己的 localhost），这是访问被管机上既有 sshd、数据库等服务的标准路径。

断线重连。连接断开后按指数退避自动重连（1 秒起步、60 秒封顶、附加随机抖动），注册状态持久化，重连后无需重新注册。连接断开时进行中的会话随之结束，CLI 明确报错；不做会话恢复，行为与 ssh 断线一致。

CLI 登录。`exvia login` 用管理员凭证换取会话令牌，保存在本地（0600），后续命令免登录。

多用户与授权。在管理员之下引入普通用户，控制每台机器允许哪些用户访问。

CLI 信任白名单。最终授权落在被控端本地：agent 维护一份受信 CLI 公钥白名单（`trust list/add/rm`），会话票据必须由白名单内的私钥签名才被接受。用户名由 CLI 在票据中自报（在签名覆盖范围内，中继不可篡改），agent 无法核对其对应哪个人，日志以 `claimed_user=` 标注；授权依据是签名本身，不是这个名字。新增操作者或重装 CLI 后，需要把新公钥补进目标机器的白名单。

连接治理。中继对"连上了却不完成认证"的连接不无限等待：注册、登录、上线握手各有 15 秒绝对期限，超时强制断开，防慢速连接悬挂占用资源；被拒登录立即返回原因，不让客户端空等超时。

审计日志。中继记录会话事件：时间、用户、机器、会话类型、时长、传输字节数，支持导出。

运维可观测性。中继可选开启一个仅绑定本机回环地址的指标端点（`--metrics-listen`），输出在线机器数、活跃会话数、累计传输量等运行指标，供本机或 ssh 隧道内的监控系统抓取，不对公网暴露。证书与管理员令牌有生命周期管理：中继证书有效期可配置（默认 10 年）并记录在旁挂元数据里，剩余不足 30 天或已过期时每次启动给出提醒（TLS 层刻意不做硬过期校验，避免到期瞬间全线下线）；管理员令牌支持轮换，超一年未轮换给出提示。

机器分组。机器打标签，`exvia ls` 按标签过滤。

升级辅助。被控端上报版本，协议不兼容时中继在 CLI 明确提示升级路径。

下面这些目前没有实现：QUIC 传输（受限网络到中继的 UDP 443 实测可达且稳定时可作为首选，WSS 始终作兜底，两种传输共用同一会话协议）；中继可选的 XDP 入站过滤（对端口扫描隐身并缩小攻击面，仅中继侧部署选项，默认关闭）；SOCKS5 动态转发；用正规证书（ACME/Let's Encrypt）替代自签证书；Web 管理界面；L3 组网（把被管机拉进一个虚拟网段实现多机任意互访，管理面用 exvia、数据面用 WireGuard）。L3 组网要被管机 root、可加载 eBPF（加固机或容器里 seccomp 可能禁）、可改网卡 offload，合成 TCP 流在深度 DPI 下比标准 TLS 更易识别，且属于 GPL 代码，只做进程隔离的独立集成、不并入仓库。端口转发已覆盖点到点访问，L3 组网只在需要多机任意互访时再考虑。

## 非功能性需求

网络兼容性。承载为标准的 WebSocket over TLS，能穿过常见的出站审查形态（对标准 HTTPS/WebSocket 放行即可通过），不依赖 UDP。中继监听端口可配置，不占用 443，与机器上已有或将来要部署的 HTTPS 服务不冲突。

安全性。传输层 TLS 1.3，其内再套端到端加密（Noise），双层加密、中继不可读；三处指纹固定（中继证书、会话对端公钥、机器标识）；本地密钥文件 0600；注册令牌一次性、可撤销；中继本地只存元数据不存内容。

性能。终端交互延迟在同城网络下 100ms 以内；文件传输单流吞吐 20MB/s 以上；被控端空闲时 CPU 占用接近零，常驻内存 30MB 以内。

可靠性。中继重启或网络闪断后被控端自动恢复；单个会话出错不影响其他会话和主连接；进程被系统服务自动拉起。

运行平台。被控端支持 Linux x86_64 与 aarch64，CLI 支持 macOS（Apple Silicon）和 Linux，中继跑 Linux；均以系统服务或常规进程方式运行。Windows 不在当前支持范围内。

规模。一台中继支撑 100 台机器在线、每台 8 个并发会话；不做集群和高可用。

工程质量。发布为静态链接的单二进制（linux-musl 目标；native 与 gnu 目标动态链接 libc）；日志分级可配置；依赖入库前审查 license，不引入 GPL/AGPL 代码——别人的协议设计可以参考，代码不行。

## 约束条件

- 开发语言 Rust（stable 版本）。
- 中继以独立服务部署、独占端口，不复用现有 443 或其他 HTTPS 服务的端口；具体监听端口作为部署参数，按目标网络的放行策略选定。
- 被管机不要求安装或开启 sshd：终端和文件功能是内置的，端口转发只是对接被管机上既有服务的手段。

## 明确不做的事

- 远程桌面、GUI 操作、剪贴板同步：体量太重，也偏离运维工具定位；
- 主机层隐藏、对抗杀软和 EDR（见"安全与不可探测性"）；
- 上千台规模的集群管理、中继高可用集群；
- 点对点打洞直连、被控端多级级联；
- 内置完整的 SFTP 服务端——端口转发已经能复用真实 sshd 的 sftp，没必要重造；
- `shell` 多机批量：交互终端共用一个本地 tty 的语义是混乱的（输出交错、Ctrl-C 广播），刻意只做单机；批量场景用 `exec` / `put` 的多机形式。

## 验证方式

1. 用 iptables 把测试环境配成只放行中继监听的那一个出站 TCP 端口（禁 UDP），完整走通注册、终端、传文件、端口转发全流程；
2. 在中继上抓包，会话内容不可读；翻中继本地数据库，只有元数据、没有任何会话明文；
3. 用浏览器直接访问中继端口，看到的是一个正常网页，而不是协议报错或异常特征；
4. 被控端以系统服务运行：开机自启、进程杀掉后自动拉起；
5. 断网一分钟再恢复，被控端自动重连，全程无人工干预；
6. `exvia shell` 里开 vim、htop 一切正常，拉伸终端窗口后显示不错乱，远端退出后能拿到正确的退出码；
7. 传一个 100MB 的文件，收发两端 SHA-256 一致；
8. 通过端口转发，用系统自带 ssh 客户端成功登录目标机器。
9. `put -r` 传一个目录树，远端 `diff -r` 比对内容、权限位与修改时间一致；把传输进程强杀后用 `--resume` 续传，完成后的文件哈希与源一致，陈旧或超长的本地分片不会被拼接进结果。
